Authentication

For MyFmHub platform admins only. This guide explains how logins, organisations, people, sign-in and sessions fit together, so you can answer customers' questions and sort out sign-in problems.

Logins and people

MyFmHub keeps two separate things:

  • A login is an email address that can sign in. There's only ever one login for an email, however many organisations it's in.
  • A person is someone in one organisation, as listed on its People page. A person always has a login, and that login can have a person in several organisations.

For example, a contractor who works for two customers has one login, bob@contractor.com, and a person in each customer's organisation. Each customer controls its own person record, and nothing either of them does changes what Bob can do in the other one.

There are no passwords. Everyone signs in with a code emailed to them.

Signing in

  1. They enter their email on the sign-in page and we email them a 6-digit code.
  2. They enter the code, or click the link in the email to get to the code page.
  3. MyFmHub picks the organisation to open (see below) and signs them in.

Codes have these limits:

  • A code lasts {{ code_minutes }} minutes and can only be used once. Asking for a new code cancels the old one.
  • After {{ code_attempts }} wrong attempts a code stops working, and they need a new one.
  • One new code a minute, and {{ codes_per_hour }} an hour, per login. This includes sign-in emails sent when someone is added to an organisation, so an invite can be refused if they've just asked for a code.
  • The code page has a Send a new code button for when an email doesn't arrive or a code has run out.

If the email isn't a login at all, the sign-in page says it couldn't find an account. That does tell someone whether an email has an account, which is a known trade-off.

Which organisation opens

A login can only go into an organisation where its person has Can log in turned on, and the organisation isn't suspended and has been verified (see Registering). Of those, MyFmHub opens:

  1. the organisation the code was sent for, when it came from an invite or a registration
  2. otherwise the organisation they last worked in
  3. otherwise their only organisation
  4. otherwise, when they're in several and none of the above applies, a page asking them to choose

Switching organisation

Someone who can sign in to more than one organisation sees Switch organisation in the account menu (the person icon, top right). It lists their organisations by name. Choosing one takes them to its dashboard, because records belong to one organisation and the page they were on may not exist in the other. The account menu always shows which organisation they're working in.

Each signed-in device works in one organisation at a time, so someone can have one organisation open on their laptop and another on their phone. Next time they sign in, MyFmHub opens the one they used last.

Registering an organisation

Anyone can register a new organisation from the registration page. They become its first person, in the Admin group with Can log in on.

  • An email that's already a login can register too. The new organisation is added to that login, so someone can run several organisations with one email.
  • Because anyone can type any email, a new organisation starts unverified. It isn't offered at sign-in or in Switch organisation until someone enters the code that was emailed when it was registered. That stops a stranger adding junk organisations to someone else's login.
  • If the code email doesn't arrive, Send a new code on the code page sends another code for the same organisation, so it can still be verified. Signing in normally from the sign-in page doesn't verify it.
  • Unverified organisations show an Unverified badge under Admin › Organisations. They aren't deleted automatically.

Adding people

  • An organisation adds people on its People page, or imports them. If the email is already a login elsewhere, the new person is linked to that same login. The organisation isn't told the email is in use elsewhere: adding it looks exactly the same as adding a brand new email.
  • The same email can't be in one organisation twice.
  • With Can log in on, MyFmHub emails them a code saying who added them to which organisation. That code opens the organisation that sent it. With Can log in off, nobody is emailed: the person is just a record, for example a contact.
  • Turning Can log in on later sends the same email, and Resend sign-in email on their record sends another.
  • Imported people never have Can log in on, so imports never email anyone.

Changing someone's email

Changing a person's email never changes the login, because the login may be used by other organisations. Instead the person moves to the login for the new email, which is created if it doesn't exist yet. Their sessions in that organisation end, as they signed in with the old email, and if Can log in is on they're emailed a code at the new address.

This protects people who are in more than one organisation: one organisation can't change Bob's email to an address it controls and then sign in as Bob somewhere else. If the old login isn't used by anyone any more, it's deleted. Someone who changes their own email is signed out and signs in again with the new one.

Removing access

  • Turning off Can log in stops them signing in to that organisation and ends their sessions working in it. Their other organisations aren't affected. If it was their only organisation, they can't sign in at all and are told to ask an admin.
  • Deleting a person removes them from that organisation and ends their sessions there. Their login is deleted too only if they aren't in any other organisation.
  • Nobody can turn off their own Can log in or delete themselves, and every organisation must keep at least one admin who can log in.

User groups and admins

User groups belong to each organisation, so the same login can be an admin in one organisation and have view-only access in another. The Admin group always has full access, including user groups, everyone's sessions and organisation settings. Only admins can put someone in the Admin group, or edit or delete an admin.

Sessions

Each sign-in on a device is a session. It lasts {{ session_days }} days unless they sign out or it's revoked.

  • Everyone can see their own sessions under Your sessions in the account menu, across all their organisations, and revoke any of them, for example on a lost phone.
  • Organisation admins see Sessions instead: every session working in their organisation, plus their own. They don't see someone's sessions in other organisations, because the devices and IP addresses there are none of their business.
  • Revoking a session signs that device out. It doesn't stop them signing in again: to do that, turn off Can log in on their person record.

Suspending an organisation

Under Admin › Organisations a platform admin can suspend an organisation, for example for unpaid bills. Nobody can sign in to it, and every session working in it ends. People who are in other organisations can still use those. Someone who can only get into suspended organisations sees a page saying their organisation's account is suspended, with the support email address. Reinstate undoes it. You can't suspend the organisation you're working in.

Platform admins

  • Platform admin access is given on the server with flask make-platform-admin <email>, and taken away with --remove. It can't be given from inside the app.
  • The email doesn't need to be in any organisation: a new email gets a login with no organisation, which signs in straight to Admin. Removing access from a login with no organisation deletes it.
  • A platform admin can also be a person in organisations, like anyone else. Admin is in the account menu whichever organisation they're in.
  • Admin › Users lists every login with its organisations. Revoke sessions there signs the login out everywhere, in every organisation. Admin › Sessions can revoke one session, every session in an organisation, or every session everywhere, for example after a security incident.

When someone can't sign in

Check these in order:

  1. Is it the right email? Search for it under Admin › Users. If it isn't there, there's no login: their organisation needs to add them.
  2. Is Can log in on? Admin › Users shows "No login" when none of their people can log in. Their organisation's admin turns it on from the person record.
  3. Is the organisation suspended or unverified? "Organisation unavailable" in Admin › Users means they can log in somewhere, but every such organisation is suspended or still unverified.
  4. Is the code being refused? It may have run out, been used, been replaced by a newer code or had too many wrong attempts. Send a new code fixes all of these.
  5. Too many codes? They may have to wait a minute, or up to an hour after {{ codes_per_hour }} codes.
  6. Can't see an organisation they expect? Check that it's verified, not suspended, and that their person there has Can log in on.
